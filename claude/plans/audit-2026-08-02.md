# Audit and hardening, 2026-08-02

What was asked for, what was found, what was done, and what is left. This
supersedes the working file in `~/.claude/plans/`, which was written before most
of the verification and is wrong in the way this note explains.

## What happened

An audit of the whole project — pod load first, then security, federation
robustness, storage integrity, code quality, and later the `web/admin/` UI for
accessibility. Then the findings were verified. Then they were fixed. Then the
FIXES were reviewed, which turned out to matter more than any of it.

25 commits. `claude/smoke-tests`: **464 → 702 checks**, green throughout.

## The thing worth remembering

**Reviewing the fix caught more than reviewing the code did.**

The eight section-E fixes went in green, with tests. An adversarial review of
that commit found **nine defects in them, four of which were regressions** —
behaviour that worked before the fix and did not after:

- The `UNREADABLE` lease sentinel was added so "could not ask" would stop
  reading as "nobody holds it" — and then `renewOnce`'s ownership test was not
  updated. A Symbol is truthy with an undefined `.holder`, so one transient pod
  GET read as a takeover and demoted a healthy agent. The old code did not.
- The per-host delivery breaker cooled the host on *any* error, so a `410 Gone`
  for one departed follower starved every other follower on that instance.
- A `503` with no `Retry-After` — most of them — collapsed the exponential
  ladder to a flat 60s. That is the hammering shape the 2026-07-29 postmortem
  exists for, introduced by the commit that claimed to fix it.
- The widened `Undo` gate accepted `object: undefined/null/{}`, which land on
  the no-`followId` carve-out and evict. Those records are exactly what
  `reconcileFollowers` writes recovering a restored machine — so it reopened the
  eviction hole closed eight commits earlier, by the same author, the same day.

Green tests meant the tests did not cover the case. They did not mean the code
was right.

## The other thing worth remembering

**A high-severity sample predicts badly.** 19 findings were verified first,
chosen because the reviewers ranked them most severe; every one came back with
its mechanism or severity corrected, and the conclusion drawn was that the
unverified tail (section E, 58 findings) would be mostly noise.

It was not. Of 46 E claims that got a verdict, **41 survived** — 26 confirmed as
filed, 15 adjusted, 3 refuted, 2 already fixed. Severity is precisely what an
over-claiming reviewer inflates, so the *most* severe findings are the least
reliable ones. The modest tail was the accurate part.

## What was fixed

**Pod load.** A follower event went from 9 requests to 2 (`publishCollections`
now takes what changed; the three ACLs are pure functions of the WebID and are
written once, by `publishProfile`). A demoted agent stops renewing its lease —
it used to pay ~80 requests/hour forever and could silently re-claim the lease
with a cached ETag. Every write and delete honours `Retry-After`; only reads did.
The unauthenticated public-surface probes are counted and cooled like everything
else. A flapping push socket no longer resets its backoff on an unstable open.

**Remote load.** The delivery queue got the hardening the inbound side got after
the incident: a re-entrancy latch, a 15s deadline, per-host cooling that
distinguishes a refusal about the *server* from one about a *recipient*, a
jittered ladder, and `Retry-After` honoured up to a day. The tag feed sleeps on a
15-minute-to-6-hour ladder instead of polling a struggling instance on cadence.

**Security.** Inbound `Update` gained the known-actor guard `onDelete` has had
all along. `Undo{Follow}` must name the follow it revokes — omitting the id used
to evict any follower named. The SSRF filter matched only the dotted spelling of
a v4-mapped IPv6 address, which is the one the URL parser never produces, so
every private range was reachable as `[::ffff:7f00:1]`. Remote bios, names and
avatar URLs are sanitized where they enter the store — `sanitize-html` covered
note content and not the other thing a stranger writes. `serveStatic` decoded
before splitting, so `/..%2fpackage.json` served the file; the mount is resolved
and contained now. `/shutdown` was the one state-changing route above both
gates. An `http://` pod or issuer off this machine is refused at setup.
Unverifiable inbound Follows for a person wait in a queue.

**Integrity.** Commit-before-delete lost its same-origin exemption, and
`commit()` stopped reporting success for writes whose debounce fired on its own.
A pod error on an inbox item no longer destroys the delivery. Keys and
credentials are written atomically. `HttpStorage` got the jail `FileStorage`
had. `aclDoc` was the last hand-built Turtle in the tree and now goes through
rdflib. Inbound `Reject` and `Move` are handled. `actors.json` and `agent.log`
are bounded. The fediverse's other content types — Article, Question, Video,
Page — are no longer dead-lettered as "not a verifiable Note".

**Accessibility.** Every text colour already passed AA; the failures were
elsewhere. The record page had no scroll container at all, so at zoom its lower
half was unreachable — fixed on the column, not the window, which is what the
never-scroll rule actually asks for. The floating panel is a dialog that takes
and returns focus. The actor picker no longer navigates on `change`. `lang`,
`role="alert"`, control-boundary contrast, and the bar wrapping at 320px, which
a browser found and the audit had not.

## What is left

Nothing confirmed is reachable by a remote party under a loopback install.

**Deferred with reasons, all real:**
- `publishProfile` rewrites ~34 documents on every save. A digest gate would
  skip the repair path — which exists precisely for when the digest lies.
- `outbox.json` is uncapped. It is the index `rebuild` reads to recover posts.
- `ids.json` is uncapped and linearly scanned. Client references to older
  statuses resolve through it.
- `/oauth/revoke` is a no-op; `activitypod tokens --revoke` works.

**Open decisions:**
- `/admin/` authentication. Defence-in-depth under loopback, since anyone who
  can reach the port can already read the files. It matters if `AP_ALLOWED_HOSTS`
  is ever used.
- Inbound HTTP Signature verification, which needs delivery terminated at the
  agent's own endpoint rather than the pod. It would *reduce* pod load. Separate
  plan; it changes what the pod is for.

**Low tail (~15):** pagination and `Link` headers, synchronous static reads, CSP
`connect-src https:`, duplicated port/spawn helpers, `.tmp` files listed as
notes, `onAccept` not checking the Accept names our Follow, raw exception
messages to callers, a symlink mount inside `ui/` escaping the lexical check.

## Verification

`npm test` — 702 offline checks, no pod, no network. Nothing here was tested
against a live pod or a live federation partner; `state --to pod` stays parked.
The accessibility and static-jail work was additionally driven in a real browser
against a running agent, which is where two of the findings came from.
