Keep your name. Lose the noise.

This host is a mail filter for FediPod accounts. Your name, your key and your data stay on your own pod — this box only receives your fediverse mail, verifies each delivery, drops the junk, and passes the rest to your pod. Leaving takes one command; nothing of yours is ever here.

What are you here to do?

Attach your FediPod

Your account stays @you@your.pod — other servers keep finding you at your own address. Attaching only changes where your mail arrives: your actor advertises this host's door as its inbox, and everything that passes verification lands in your pod as before.

Only the door is named here — it is a routing address for servers, not your handle.

Create a FediPod

A FediPod is two things you own: a pod (always-on storage with your name on it) and an agent (the app you read and post from, on any of your machines). A browser cannot install the agent for you — there is exactly one command to run.

  1. Get a pod, if you don't have one: any Solid pod host that offers https subdomains works, or a Community Solid Server you run yourself.
  2. Install and start the agent on your own machine: 
    git clone https://github.com/jeff-zucker/FediPod
cd FediPod
npm install
npm start
    Setup opens in your browser and can also create the pod account for you.
  3. Come back here and attach, so this host starts filtering your mail.

This host also offers pods — you can take one at step 1 instead of bringing your own; it stays exportable, so you can leave with everything.

Run a front like this one

A front is only a doorway: a directory, name lookups, verify-and-forward. It stores no user content and dictates nobody's pod. The one choice you make is what your users do about pods:

Bring-your-pod, mandatory

Every user supplies a pod they already control, hosted wherever they like. You run the doorway and nothing else. Duties: keep the box up, keep names honest, handle detach requests and the complaints that reach the visible domain. If your box dies, mail routing pauses but nobody's data or name is lost.

Bring-your-pod, optional

Same doorway — but users who have no pod may take one from a pod service you also happen to run or recommend. That pod hosting is a separate thing (its own server, its own duties as a data custodian); the front never provides pods itself, and a user who brings their own always keeps full custody.

Setup and installer: see netlify/README.md in the FediPod repo. If you host pods on a Community Solid Server, the gateway can also run there as a component instead of on a separate box.
