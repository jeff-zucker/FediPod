FediPod - join the fediverse from a Solid pod.

Welcome to the FediPod.net gateway — a mail filter for accounts that stay yours. Your name, key and data live on your own pod; this box only receives your fediverse mail, verifies each delivery, drops spam and passes the rest to your pod. Joining and leaving the gateway is simple.

What do you want to do?

Create a new FediPod account

A FediPod is two things you own: a pod (always-on storage with your name on it) and an agent (the app you read and post from, on any of your machines). A browser cannot install the agent for you — there is exactly one command to run.

  1. Get a pod, if you don't have one: any Solid pod host that offers https subdomains works, or a Community Solid Server you run yourself.
  2. Install and start the agent on your own machine: 
    curl -fsSL https://fedipod.net/install | sh
cd ~/FediPod && npm start
    Setup opens in your browser and can also create the pod account for you. (Prefer to see what you run? The installer is plain shell at /install, or clone the repo yourself.)
  3. Come back here and attach, so this gateway starts filtering your mail.

This host also offers pods — you can take one at step 1 instead of bringing your own; it stays exportable, so you can leave with everything.

Attach an existing FediPod account

Your account stays @you@your.pod — other servers keep finding you at your own address. Attaching only changes where your mail arrives: your actor advertises this gateway's door as its inbox, and everything that passes verification lands in your pod as before.

If your FediPod uses a custom root, give the full home URL (ending in /); a bare pod address assumes the default activitypods-js/.

Only the door is named here — it is a routing address for servers, not your handle.

Signing in proves the pod is yours — no password ever reaches this gateway.

Detach an existing FediPod account

Detaching is yours to do, not this gateway's — your agent republishes your actor with your pod's own inbox, and deliveries go straight there again. On your machine:

node bin/fedipod.mjs gateway --detach

Your name and data never moved, so nothing else changes. The door you had here goes quiet and its name can be reused.

Transfer a fediverse account to FediPod

The fediverse's standard migration works toward a FediPod: your followers move over automatically, and your old profile redirects. Posts stay on the old server — no fediverse migration carries them.

  1. Have a FediPod — create one first (the first option above).
  2. On your agent's admin page, set new followers to accepted automatically, so the wave of arriving followers doesn't queue.
  3. Tell your FediPod about the old account: 
    node bin/fedipod.mjs alias --add @you@old.server
  4. On the old server: Preferences → Account → Move to a different account, naming your FediPod address.
  5. Bring the rest over from the old server's CSV export: 
    node bin/fedipod.mjs import following_accounts.csv blocked_accounts.csv muted_accounts.csv lists.csv

Run a gateway like this one

You stand up your own gateway on your own box. A gateway is only a doorway: a directory, name lookups, verify-and-forward. It stores no user content and dictates nobody's pod. The one choice you make is what your users do about pods:

Bring-your-pod, mandatory

Every user supplies a pod they already control, hosted wherever they like. You run the doorway and nothing else. Duties: keep the box up, keep names honest, handle detach requests and the complaints that reach the visible domain. If your box dies, mail routing pauses but nobody's data or name is lost.

Bring-your-pod, optional

Same doorway — but users who have no pod may take one from a pod service you also happen to run or recommend. That pod hosting is a separate thing (its own server, its own duties as a data custodian); the gateway never provides pods itself, and a user who brings their own always keeps full custody.

Setup and installer: see netlify/README.md in the FediPod repo. If you host pods on a Community Solid Server, the gateway can also run there as a component instead of on a separate box.
